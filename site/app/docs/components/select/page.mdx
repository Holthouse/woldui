## Usage

<Example name="select/usage">
	<Usage />
</Example>

`SelectValue` shows the chosen item's text in the trigger, or its `placeholder` when nothing is chosen. The list is portalled to the end of `<body>`, so it is never clipped by an `overflow: hidden` parent.

## Groups

`SelectGroup` with a `SelectLabel` gives a run of items a heading. `SelectSeparator` draws a line between groups.

<Example name="select/groups">
	<Groups />
</Example>

## Sizes

`size` on `SelectTrigger` is `default` or `sm`. The trigger is `w-fit` unless you give it a width.

<Example name="select/sizes">
	<Sizes />
</Example>

## States

`disabled` on `Select` disables the whole control, and `disabled` on a `SelectItem` skips just that option. `aria-invalid` on the trigger draws the danger border.

## Positioning

By default (`position="item-aligned"`) the list opens so the chosen item sits over the trigger, as a macOS menu does. `position="popper"` opens it below the trigger instead, like a dropdown, and scrolls when it runs out of room.

## Accessibility

- The trigger is a `<button role="combobox">` with `aria-expanded`. Enter, Space and the arrow keys open it.
- In the open list, the arrow keys move between items, Home and End jump to the ends, typing a letter jumps to the next matching item, Enter selects, and Escape closes and returns focus to the trigger.
- Label it by giving `SelectTrigger` an `id` that a `Label`'s `htmlFor` points to, or an `aria-label` when there is no visible label.
- Mark an invalid select with `aria-invalid` on the trigger and point `aria-describedby` at the message.
- Inside a `<form>`, a hidden native `<select>` carries `name` and the chosen value, so it submits and autofills like a native one.
