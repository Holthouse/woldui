## Usage

<Example name="field/usage" align="start">
	<Usage />
</Example>

`Field` stacks a label, control, description and error. `orientation="horizontal"` puts the label and control on one row, which suits switches and checkboxes. `responsive` stacks on narrow containers and goes horizontal once its `FieldGroup` is at least the `md` container width. Set `data-invalid` on a `Field` to turn its text to the danger colour.

## Checkbox group

A `FieldSet` with a `FieldLegend` names a set of controls. `variant="label"` makes the legend the size of a field label.

<Example name="field/checkbox-group" align="start">
	<CheckboxGroup />
</Example>

## Choice cards

A `Field` wrapped in a `FieldLabel` becomes a bordered card that highlights when its control is checked. `FieldTitle` gives the card a heading that is not itself a label.

</Example>

## Accessibility

- `FieldSet` and `FieldLegend` render a native `<fieldset>` and `<legend>`, so the legend is announced as the group's name.
- `Field` renders with `role="group"`. The label is associated through `htmlFor`, not through the group.
- Nothing here sets `aria-describedby` or `aria-invalid`. Give the description and error an `id` and list them on the control.
- `FieldError` renders with `role="alert"`, so it is announced as soon as it appears. It also accepts `errors`, an array of `{ message }` objects, and de-duplicates them.
