## Usage

<Example name="tabs/usage" align="start">
	<Usage />
</Example>

Switch tabs: the pill slides from one trigger to the next rather than reappearing. That is a shared-layout animation (Motion's `layoutId`), the one movement here that CSS cannot express. Each `TabsList` scopes its own pill, so two tab sets on a page never animate into each other.

## Line

`variant="line"` on `TabsList` swaps the pill for an underline that slides the same way.

## Vertical

`orientation="vertical"` stacks the triggers beside the panel. The arrow keys follow the orientation: Up and Down move between vertical tabs.

## Accessibility

- The list, triggers and panels get the `tablist`, `tab` and `tabpanel` roles, with `aria-selected` and `aria-controls` wired up by Radix.
- Tab moves focus into the list and then on to the active panel. The arrow keys move between triggers, and Home and End jump to the first and last.
- By default a trigger activates as soon as it gets focus. Set `activationMode="manual"` on `Tabs` when switching is expensive, so the user presses Enter or Space to confirm.
- The sliding pill is `aria-hidden`. Under `prefers-reduced-motion` it jumps to the new trigger instead of travelling.
- Icons inside a trigger are decorative. Keep a text label, or give an icon-only trigger an `aria-label`.
