`CarouselPrevious` and `CarouselNext` sit outside the carousel's edges and disable themselves at either end. Give the carousel's wrapper horizontal padding so they stay in view.

## Several per view

A `basis-*` class on `CarouselItem` sets how much of the row each slide takes, and it can change at a breakpoint. The arrows are optional: without them the carousel still drags and swipes. `opts` passes options straight to Embla, here `align: 'start'`.

## Using the API

`setApi` hands you Embla's API once it is ready. Listen to its `select` event to track the current slide, or call `scrollTo` to drive it from elsewhere.

## Accessibility

- The root is a `region` with `aria-roledescription="carousel"`, and each item is a `group` with `aria-roledescription="slide"`. Give the carousel an `aria-label`, and each slide one that says where it is ("2 of 4").
- The arrow buttons carry "Previous slide" and "Next slide" as screen-reader text.
- Left and Right arrow keys move the carousel while focus is anywhere inside it, including on the arrow buttons. The root itself is not focusable, so a carousel with no arrows and no links or buttons in its slides can't be reached by keyboard at all. Keep the arrows unless the slides are interactive.
- Nothing plays automatically. If you add Embla's autoplay plugin, add a pause control too.
- `orientation="vertical"` turns the whole thing on its side, but the keyboard handler still listens only for Left and Right.
