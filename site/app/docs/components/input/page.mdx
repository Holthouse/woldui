## Types

`Input` is a styled native `<input>`, so every `type` works as the browser defines it. `file` gets a matching button style.

## States

`disabled` dims the field and takes it out of the tab order. `readOnly` keeps it focusable and selectable. `aria-invalid` turns the border and fill to the danger colour, and is the only thing that does: there is no separate `invalid` prop.

## With the Field atom

The [Field atom](/docs/atoms/field/) (`@woldui/react/components/atoms/field`) is the accessible label, control, description and error as one unit. It hands the control its `id`, `aria-describedby` and `aria-invalid` through a render prop, so the wiring cannot drift. Reach for it in real forms.

<Example name="input/with-field">
	<WithField />
</Example>

<Callout>
	The Field atom takes a render prop, which is a function, so a page that uses it must be a client
	component (`'use client'`).
</Callout>

## Accessibility

- It renders a native `<input>`, so autofill, spell-check, the on-screen keyboard for each `type` and form submission all work unchanged.
- Label every input. Use `Label` with `htmlFor`, the Field atom, or an `aria-label` only where a visible label truly does not fit (a search box beside a search icon, say). A placeholder is not a label.
- Mark an invalid field with `aria-invalid` and point `aria-describedby` at the message that explains it. The Field atom does both.
- The focus style is a 2px primary border and a lifted fill, and it shows on mouse focus as well as keyboard focus.
- Set `autoComplete` on personal details (`email`, `name`, `current-password`) so browsers and password managers can fill them.
