## With a form

Put the `<form>` inside `DialogContent` so the footer's submit button belongs to it. Here the dialog is controlled, so it closes only once the name validates. The `Field` atom wires the label, `aria-invalid` and the error message.

## Controlled

Pass `open` and `onOpenChange` to drive the dialog from your own state. You need this when the thing that opens it is not a `DialogTrigger`, such as a menu item: a trigger inside a menu is unmounted when the menu closes, taking the dialog with it.

## Destructive confirmation

To confirm something irreversible, use [Alert Dialog](/docs/components/alert-dialog) instead. It has the same look, but clicking outside does not dismiss it, and it opens with focus on Cancel, so the user has to make an explicit choice.

## Long content

The dialog grows with its content. When the content could be taller than the screen, cap the height and let only the body scroll, so the title and the actions stay in view.

## Close button

`DialogContent` draws a close button in the corner by default. `showCloseButton={false}` removes it. `DialogFooter` has its own `showCloseButton`, which adds a labelled Close button to the footer instead.

## Accessibility

- Focus moves into the dialog when it opens and is trapped there: Tab and Shift+Tab cycle through its controls only, and the page behind is hidden from screen readers.
- Escape closes it, as does clicking the backdrop. When it closes, focus returns to the `DialogTrigger` that opened it. A controlled dialog with no trigger returns focus to whatever had it before; use `onCloseAutoFocus` on `DialogContent` to send it somewhere specific.
- `DialogTitle` is required: it becomes the dialog's accessible name, and Radix warns in development if it is missing. If your design has no visible title, keep it and hide it with `className="sr-only"`. `DialogDescription` is announced as the description. Leave it out only if you also pass `aria-describedby={undefined}` to `DialogContent`.
- The corner close button is an icon with a screen-reader-only "Close" label. If you remove it with `showCloseButton={false}`, keep another visible way out, such as a footer button.
- The entrance and exit are CSS animations. Under `prefers-reduced-motion`, the global guard collapses them, so the dialog appears and disappears at its final size with no scale or fade.
